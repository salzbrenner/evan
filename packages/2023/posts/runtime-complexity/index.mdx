Runtime complexity describes the performance of an algorithm.

How much more processing power or time is needed to run an algorithm if the input is doubled?

## O(1)

Contstant time. No matter the input, the algo will always take the same amount of time.

## O(log(n))

Logarithmic time. When doubling the number of elements you are iterating over does not double the amount of work. Always assume search operations are log(n).

## O(n)

Linear run time. Iterating through all the elements in a collection of data. Loops from 0 to array.length. Each additional element = 1 additional step through 1 loop.

## O(n \* log(n))

Quasilinear time. Doubling the elements you are iterating over doesn't double the amout of work. Adding one element adds something like 1 + \<1 more time/work.

## O(n^2)

Quadratic. n ^ 2. Each additional element has to interact with every other element. "Handshake problem" - each person in room has to shakes hands, and every new person has to shake everyone's hands.

## O(2^n)

Exponential time. If you add a single element, the processing power needed doubles (or dramtically increases if not doubles).
